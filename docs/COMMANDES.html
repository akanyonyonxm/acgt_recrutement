Guide des commandes d'administration — ACGT

Comment lancer et utiliser les commandes de gestion de la plateforme de recrutement.

Comment lancer une commande

Toutes les commandes se lancent sur le serveur (connecté en SSH), dans le dossier du projet (/opt/acgt_recrutement), via le conteneur backend :

docker compose -f docker-compose.prod.yml exec backend python manage.py <commande>

Remplacez <commande> par le nom voulu (voir ci-dessous). En local (développement), on utilise plutôt venv\Scripts\python.exe manage.py <commande> depuis le dossier backend/.

Codes couleur : lecture seule n'écrit rien · modifie des données écrit en base (non destructif) · destructif à manier avec précaution.

1. Rattachement des dossiers à la liste d'éligibilité

corriger_rattachements modifie des données

Réconcilie le rattachement de tous les dossiers soumis avec la liste d'éligibilité. Un dossier est rattaché à une personne de la liste uniquement si le nom complet est identique (nom ET postnom ET prénom — insensible aux accents et à la casse), et si la correspondance est unique. Le code n'entre jamais en jeu (des candidats saisissent le code d'autrui).

La commande : rattache ceux qui correspondent et ne le sont pas encore, conserve les rattachements corrects, détache ceux faits à tort (triche par code).

Toujours simuler d'abord (n'écrit rien, affiche ce qui serait changé) :

docker compose -f docker-compose.prod.yml exec backend python manage.py corriger_rattachements --simuler

Si le récapitulatif convient, appliquer :

docker compose -f docker-compose.prod.yml exec backend python manage.py corriger_rattachements

Le résumé indique : « X nouveaux rattachements, Y rerattachés, Z détachés, W conservés ». La commande est idempotente (on peut la relancer sans risque) et non destructive (elle ne touche que le champ de rattachement, aucune donnée n'est supprimée).

correspondances_a_verifier lecture seule

Liste les dossiers non rattachés dont le nom partage avec une personne de la liste le même nom + postnom, ou le même nom + prénom — typiquement une coquille (ex. prénom « Achillene » au lieu d'« Archillene ») ou un champ manquant. Affiche côte à côte les noms complets et les codes, pour vérification manuelle.

docker compose -f docker-compose.prod.yml exec backend python manage.py correspondances_a_verifier

Exemple de sortie :

DOSSIER #1483 [0599] YAKONGBO SIKI Achillene
   ~ LISTE  [0599] YAKONGBO SIKI Archillene   (nom+postnom)

Pour chacun, ouvrez la fiche du dossier dans Validation → Ouvrir, vérifiez qu'il s'agit bien de la même personne, puis cliquez sur la carte de correspondance pour la sélectionner et approuvez (rattachement manuel). Cette commande n'écrit rien.

2. Liste d'éligibilité

import_eligibilite modifie des données option --vider

Importe la liste des personnes éligibles depuis un fichier Excel (.xlsx, colonnes code, nom, postnom, prenom, type, annee, reference).

# Ajouter/mettre à jour sans rien supprimer
docker compose -f docker-compose.prod.yml exec backend python manage.py import_eligibilite fichier.xlsx --publier

# Remplacer toute la liste (VIDE l'ancienne d'abord)
docker compose -f docker-compose.prod.yml exec backend python manage.py import_eligibilite fichier.xlsx --vider --publier
Attention : --vider supprime la liste existante avant l'import. À n'utiliser que pour un remplacement complet et volontaire.

3. Comptes, rôles et référentiels

CommandeRôle
init_roles écrit Crée les groupes Administrateurs et Évaluateurs (idempotent).
init_postes écrit Crée les postes/fonctions de référence (Ingénieur civil, Architecte…).
init_types_piece écrit Crée les types de pièces (Identité, CV, Diplôme…).
createsuperuser écrit Crée un compte administrateur technique (demande l'email + mot de passe).
docker compose -f docker-compose.prod.yml exec backend python manage.py init_roles

4. Emails en masse

envoyer_emails_en_attente envoie des emails

Vide la file d'attente des emails en masse (convocations…), par lots, pour respecter la limite d'envoi.

docker compose -f docker-compose.prod.yml exec backend python manage.py envoyer_emails_en_attente --limite 90

5. Sauvegarde et réinitialisation

Ces opérations ont leur propre guide détaillé :

  • Sauvegarde (base + documents) : voir SAUVEGARDE.html — script scripts/sauvegarde.sh.
  • Réinitialisation des données destructif : voir REINITIALISATION.md — commande reinitialiser_donnees (exige --confirmer, conserve le compte administrateur).
Règle impérative : aucune commande destructive (réinitialisation, import --vider, suppression) ne doit jamais être lancée par le déploiement automatique. Elles se lancent uniquement à la main, et après une sauvegarde.
